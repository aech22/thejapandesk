# src/data/itineraries — 実行可能な工程表の単一ソース

旅程記事の「何時に・何分」はすべてここの JSON が持つ。記事本文（.mdx）には**時刻・所要時間・開館時間を書かない**。
`DayPlan.astro` が描画し、`scripts/check_itinerary.mjs` が機械検算する。

## 数字の2階層（AFFILIATE.md の「事実とLLM生成物を分離」の適用）

| 階層 | 何 | 置き場 | ルール |
|---|---|---|---|
| **事実** | 開館時間・最終入場・料金・休館日 | `block.fact` | `source`（一次ソースURL）と `checkedAt` が**必須**。裏が取れないものは `fact` を書かない |
| **設計値** | 滞在時間・徒歩時間・バッファ・休憩 | `block.min` / `breakdown` | 「計画上の見積り」として表示される。事実の主張はしない |
| **書かない** | 個別列車の発車時刻（「09:12発のぞみ213号」） | — | ダイヤ改正で腐る。所要時間＋運行頻度で表現する |

## ブロックの種類

| kind | 用途 |
|---|---|
| `spot` | 観光・滞在 |
| `move` | 移動。`breakdown` で徒歩／乗車／駅内に分解する（合計が `min` と一致しないと検算で落ちる） |
| `pit` | トイレ・コンビニ・水。**「行きたくなったら」ではなく「ここで取らないと次で詰まる」位置に置く** |
| `meal` | 食事。行列待ちを含んだ実測寄りの長さにする |
| `rest` | 座る休憩。歩き続ける区間に必ず挟む |
| `flex` | 意図的な空き。遅延の吸収枠。1日60分以上ないと検算で落ちる |
| `admin` | チェックイン・荷物・チケット受け取り・出国手続き等 |

## 時刻の決め方

**各ブロックに時刻は書かない。** 書くのは `day.start` と各ブロックの `min` だけで、時刻は積み上げで計算する。
手で書いた時刻が算数と合わなくなる事故を構造的に防ぐため。

- `anchor: "HH:MM"` … 時間指定入場など、その時刻に間に合っていないと成立しないブロック。積み上げ結果が anchor を過ぎていたら検算で落ちる（＝行程が破綻している証拠）
- `mustStartBy: "HH:MM"` … 最終入場・搭乗手続き締切。積み上げ結果がこれを過ぎていたら落ちる

## 追加するとき

1. JSON を足す
2. `npm run check:itinerary` を通す（**失敗したまま公開しない**）
3. 記事（.mdx）から `<DayPlan plan="<id>" day={n} />` で差し込む
